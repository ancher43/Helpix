## 💡 Архитектура и реализованный функционал

### 1. Гибридный поиск (Hybrid Search) на базе RRF
Система одновременно выполняет два независимых алгоритма поиска с последующим слиянием рангов:
1. **Полнотекстовый поиск (Lexical Search):** поиск по точным вхождениям терминов, ключевым словам и тегам в заголовках, аннотациях и содержимом статей (с поддержкой русской и латинской телеком-терминологии).
2. **Семантический поиск (Dense Vector Search):** векторизация запроса нейросетевой моделью `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` (384-мерные нормализованные эмбеддинги) и ранжирование по косинусному сходству с пороговой фильтрацией (`SEMANTIC_SIMILARITY_THRESHOLD = 0.30`).
3. **Объединение по формуле RRF (Reciprocal Rank Fusion):**
   $$RRF(d) = \sum_{m \in M} \frac{1}{k + r_m(d)}$$
   где $k = 60$ — константа сглаживания, $r_m(d)$ — порядковый номер документа в $m$-й системе ранжирования.  
   *Преимущество:* метод не требует взаимной калибровки разнородных шкал оценок и устойчив к специфическим аномалиям отдельных алгоритмов.

### 2. Умная регистрация и выявление поисковых пробелов (Knowledge Gaps)
Система регистрирует запрос как **поисковый пробел знаний** по строгим правилам, исключающим ложные срабатывания:
* **Автоматически:** только если **все три алгоритма** (полнотекстовый, векторный и гибридный) вернули 0 результатов. Если хотя бы один алгоритм нашёл решение, запрос не помечается как пробел автоматически.
* **По обратной связи оператора:** если оператор нашёл статью, но нажал кнопку **«Ответ не помог»** (материал устарел или неполон) либо вручную отправил тему в очередь на разработку.

### 3. Алгоритм NLP-кластеризации пробелов знаний
* **Иерархическая агломеративная кластеризация (Agglomerative Clustering):**
  * Динамический расчет числа кластеров $k = \max(3, \min(\lfloor\sqrt{N \cdot 2.3}\rfloor, 20))$, обеспечивающий детальное разбиение на 14–16 прикладных тем вместо укрупненных групп.
  * Метрика расстояния — косинусная (`cosine`), метод связывания — среднее (`average linkage`).
  * Контроль качества разбиения по коэффициенту силуэта (**Silhouette Score** $\approx 0.39-0.42$).
* **Обработка единичных запросов-выбросов (Singletons):** запросы, не набравшие минимальный размер кластера, автоматически объединяются с ближайшим центроидом по косинусной близости, гарантируя отсутствие потерянных данных.
* **Генерация названий тем:**
  * Нахождение медоида кластера (запроса, наиболее близкого к векторному центроиду).
  * Очистка от избыточных префиксов («как настроить», «почему не работает»).
  * Автоматическое форматирование телеком-акронимов и брендов через регулярные выражения (`IPv6`, `Wi-Fi`, `P2P`, `POS`, `СБП`, `ОФД`, `VPN`, `DNS`, `DHCP`, `GPON`, `Keenetic`, `Hikvision`, `Dahua`, `WireGuard`).
  * Извлечение ключевых тегов темы методом **TF-IDF**.

### 4. Интерактивная 3D-визуализация кластеров (Three.js / WebGL)
* Проекция 384-мерного семантического пространства запросов в трехмерные координаты $(x, y, z)$ методом **3D PCA** (Principal Component Analysis).
* Интерактивная сцена на Three.js:
  * Центроиды выявленных тем с цветовой дифференциацией.
  * Облако точек (векторы обращений операторов) вокруг центроидов.
  * Управление камерой с помощью `OrbitControls` (вращение, панорамирование, зум).
  * Интерактивные тултипы при наведении с отображением текста запроса, темы и координат.
  * Вывод процента объясненной дисперсии по трем главным компонентам.
  * Быстрое переключение между карточками и 3D-картой.

### 5. Полноэкранный детальный просмотр темы (Cluster Detail Modal)
* Открытие по клику на любую карточку темы:
  * Полный заголовок без обрезки и многоточий.
  * Бейдж статуса темы («Новый», «В работе», «Решено») с датами выявления и решения.
  * Сводные метрики: количество запросов с правильным склонением числительных (*«12 запросов»*, *«2 запроса»*), 3D-координаты центроида.
  * **Разграничение прав (RBAC):** переводить тему в статус «Решено» разрешено **только Администратору** (для модератора опция заблокирована на клиенте и защищена кодом HTTP 403 на сервере).
  * **Административное удаление:** возможность администратора удалить кластер с безопасным откреплением запросов операторов (`cluster_id = NULL`), сохраняя историю логов.
  * Полная таблица входящих запросов операторов с оценками полезности, временем выполнения и кнопкой мгновенного тестирования в поиске.
  * Баннер связанной опубликованной статьи базы знаний со ссылкой для быстрого перехода.
  * Кнопки действий: пастельная кнопка «Написать статью» (фиолетовый контур и шрифт), «Удалить кластер» (красный контур и шрифт), «Закрыть» с аккуратным контуром.

### 6. Рабочее место оператора и аналитика модератора
* Мгновенное переключение режимов поиска: *Гибридный (RRF)*, *По тексту (BM25)*, *По смыслу (Vector)* с индикацией количества совпадений по каждому алгоритму.
* Фильтрация статей по категориям с подсчетом количества публикаций.
* Плашка ранжирования под каждым результатом (RRF Score, текстовый ранг, семантический ранг, % косинусного сходства).
* Просмотр статьи в модальном окне с форматированием Markdown и кнопками обратной связи («Помогло» / «Ответ не помог»).
* Аналитический дашборд модератора: график динамики за 7 дней (Chart.js), процент непокрытых пробелов, топ частых запросов, рейтинг полезности статей, журнал поисковых логов с фильтрами и пагинацией.

## 🗄️ База данных и синхронизация

Система поддерживает двухуровневую отказоустойчивую архитектуру базы данных:
* **Основная СУБД:** **PostgreSQL** (с асинхронным драйвером `asyncpg`).
* **Резервная СУБД:** встроенная локальная **SQLite** (`aiosqlite`), активируемая при недоступности PostgreSQL для бесперебойного автономного тестирования.

### Настройка PostgreSQL (`backend/.env`):
```ini
DB_USER=postgres
DB_PASSWORD=123
DB_HOST=localhost
DB_PORT=5432       # 5432 или 5433
DB_NAME=vkr_knowledge_base
```

### Служебные скрипты (`backend/scripts/`):
* `seed_data.py` — полный засев категорий, 50 профессиональных телеком-статей, журнала запросов операторов и запуск первичной кластеризации.
* `populate_50_articles.py` — добавление расширенной базы статей для телекоммуникационной компании.
* `recalculate_3d_coordinates.py` — перерасчет 3D PCA координат центроидов и точек запросов.
* `clean_cluster_titles.py` — нормализация и форматирование названий тем.
* `sync_sqlite_to_pg.py` / `sync_clusters_to_pg.py` — двусторонняя синхронизация между SQLite и PostgreSQL.
